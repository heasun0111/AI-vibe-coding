# A-SPICE 감사원

Automotive SPICE(A-SPICE) 4.1의 프로세스 심사 모델(PAM)에 근거해 프로세스 산출물을 심사하고,
능력수준을 평정하는 방법론이다.

## 배경 지식

### 능력 수준 구조

| CL | 이름 | 핵심 |
|----|------|------|
| CL0 | 미완성 | 프로세스가 목적을 달성하지 못하거나 산출물이 없음 |
| CL1 | 수행됨 | 정의된 기본 수행 관행(BP)이 수행되고 산출물(WP)이 산출됨 (PA1.1) |
| CL2 | 관리됨 | CL1 + 성과가 계획/모니터링/조정되고(PA2.1), 산출물이 관리됨(PA2.2) |
| CL3 | 확립됨 | CL2 + 조직 표준 프로세스를 테일러링하여 사용(PA3.1, PA3.2) |
| CL4~CL5 | 예측 가능/혁신됨 | 정량적 관리, 지속적 개선 |

CL2를 점검한다는 것은 **PA1.1(프로세스 수행)이 전제된 상태에서 PA2.1(성과관리)과 PA2.2(산출물관리)**
두 프로세스 속성(PA)의 일반 수행 관행(GP)이 충족되는지를 확인하는 것이다.

### PA 2.1 성과관리 — 일반 수행 관행(GP)

| GP | 내용 | 점검 관점 |
|----|------|-----------|
| GP 2.1.1 | 프로세스 수행 목표 식별 | 일정, 품질, 자원 등 목표가 문서화되어 있는가 |
| GP 2.1.2 | 목표 달성을 위한 계획 수립 및 모니터링 | 계획서 존재, 진척 기록/이슈 로그로 실적 추적 여부 |
| GP 2.1.3 | 프로세스 성과 조정 | 계획 대비 편차 발생 시 조정(재계획, 시정조치) 근거 |
| GP 2.1.4 | 역할과 책임/권한 정의 | R&R, RACI, 역할 정의서 존재 여부 |
| GP 2.1.5 | 자원 식별 및 제공 | 인력/도구/인프라 계획 대비 실제 배정 근거 |
| GP 2.1.6 | 이해관계자 간 인터페이스 관리 | 리뷰, 커뮤니케이션, 협의 기록 |

### PA 2.2 산출물관리 — 일반 수행 관행(GP)

| GP | 내용 | 점검 관점 |
|----|------|-----------|
| GP 2.2.1 | 산출물 요구사항 정의 | 템플릿/양식, 필수 포함 항목 정의 여부 |
| GP 2.2.2 | 문서화 및 형상관리 요구사항 정의 | 형상관리 계획(CM Plan), 버전 규칙, 베이스라인 기준 |
| GP 2.2.3 | 산출물 식별·문서화·형상관리 수행 | 고유 ID, 버전, 변경이력, 저장소(베이스라인) 관리 실제 여부 |
| GP 2.2.4 | 산출물 검토 및 조정 | 리뷰 기록(리뷰어/일자/코멘트/조치), 승인 이력 |

> **주의**: 프로세스별 정확한 Base Practice 목록과 산출물(Work Product) 명칭·번호는 A-SPICE 버전과
> 프로세스 그룹(SYS/SWE/SUP/MAN/ACQ/SPL/REU/VAL/PIM/SEC/MLE)에 따라 다르다. 프로젝트에 공식
> A-SPICE 4.1 PAM 문서(PDF 등)가 있으면 반드시 그 문서를 우선 참조해 정확한 BP/WP 목록을 확인하고,
> 없을 경우 이 스킬의 일반 체크리스트를 근거로 심사하되 "PAM 원문 대조 필요"임을 리포트에 명시한다.

## 감사 절차

1. **범위 확정**: 점검 대상 프로세스(예: SWE.1, SUP.8)와 해당 산출물 목록을 사용자에게 확인하거나
   저장소/문서 저장 위치에서 탐색한다.
2. **산출물 수집**: 대상 산출물 파일(요구사항 명세, 설계 문서, 테스트 케이스, CM 계획, 리뷰 기록,
   변경이력 등)을 Read/Grep으로 확인한다.
3. **산출물 체크리스트 적용** — 아래 "산출물 유형별 세부 점검 체크리스트"에서 해당 산출물 유형의
   항목을 찾아 하나하나 확인한다. 해당 유형이 목록에 없으면 다음 공통 항목을 최소 기준으로 적용한다:
   - 식별성: 고유 ID/문서번호, 버전, 작성자·소유자 명시
   - 승인/검토 이력: 리뷰어, 리뷰 일자, 코멘트 처리 결과, 승인자 서명/승인 기록
   - 형상관리: 베이스라인 여부, 변경이력(누가/언제/무엇을 변경), 저장 위치·접근통제
   - 추적성: 상위 산출물(요구사항 등)과 하위 산출물(설계/테스트 등) 간 연결 관계
   - 배포: 이해관계자 전달·공유 근거(GP 2.1.6과 연계)
   - 계획 대비 실적: 계획서상 목표/일정과 실제 산출 시점·내용 일치 여부
4. **GP 단위 평정**: 각 GP를 ISO/IEC 33020 척도로 평정한다.
   - N (미달성, 0~15%): 증거 없음/무관
   - P (부분달성, >15~50%): 일부 증거만 존재, 체계적이지 않음
   - L (대부분달성, >50~85%): 대부분 충족, 경미한 미비점
   - F (완전달성, >85~100%): 완전히 충족, 체계적 증거 존재
   - CL2 달성 판정: 해당 프로세스의 PA2.1, PA2.2가 모두 **L 이상**이어야 CL2를 만족한다(등급 집계는
     프로세스별로 별도 수행하며, 하나라도 P 이하면 CL2 미달).
5. **근거와 갭 기록**: 평정마다 확인한 파일/문서와 구체적 근거를, 미흡한 경우 갭(Gap)과 개선 권고를 남긴다.
6. **리포트 작성**: 아래 출력 형식으로 정리한다.

## 프로세스 그룹 → 대표 산출물 유형 매핑

프로세스별 정확한 산출물 명칭·번호는 공식 PAM을 우선하되, 일반적으로 아래와 같은 산출물 유형이
생성된다. 점검 대상 프로세스를 아래에서 찾아 해당 산출물 유형의 세부 체크리스트를 적용한다.

| SYS.2 시스템 요구사항 분석 | 요구사항 명세서(시스템), 추적성 매트릭스 |

| SWE.5 소프트웨어 통합 및 통합 테스트 | 테스트 케이스/사양, 테스트 보고서 |

## 산출물 유형별 세부 점검 체크리스트

각 항목 뒤 괄호는 해당 항목이 주로 뒷받침하는 GP다. 체크 결과는 감사 절차 4단계의 평정 근거로 사용한다.

### 요구사항 명세서 (이해관계자/시스템/SW)
- 문서 ID, 버전, 작성자, 승인자가 명시되어 있다 (GP2.2.3)
- 각 요구사항에 고유 식별자(REQ-ID)가 부여되어 있다 (GP2.2.1)
- 요구사항이 검증 가능하게 서술되어 있다(모호한 표현·중의적 문장이 없다) (GP2.2.1)
- 우선순위 또는 근거가 기록되어 있다 (GP2.2.1)
- 상위 요구사항/이해관계자 요구와의 추적 링크가 존재한다 (GP2.2.3)
- 리뷰 완료 기록(리뷰어, 일자, 코멘트 처리 결과)이 있다 (GP2.2.4)
- 베이스라인이 지정되어 있고 변경이력이 관리된다 (GP2.2.2/GP2.2.3)
- 변경 시 영향분석(다른 요구사항·설계·테스트에 미치는 영향) 기록이 있다 (GP2.1.3)

### 아키텍처/설계 문서 (시스템·SW, 상세설계 포함)
- 구조 요소(컴포넌트/인터페이스)가 일관된 명명 규칙으로 식별되어 있다 (GP2.2.1)
- 요구사항과 설계 요소 간 양방향 추적 링크가 존재한다 (GP2.2.3)
- 주요 설계 결정의 근거·대안 검토(트레이드오프)가 기록되어 있다 (GP2.1.1)
- 리뷰 기록과 승인 이력이 있다 (GP2.2.4)
- 베이스라인/버전이 관리되고 변경이력이 남아있다 (GP2.2.2/GP2.2.3)
- 변경 시 영향분석 및 관련 산출물(테스트 등) 갱신 여부가 확인된다 (GP2.1.3)

### 테스트 케이스/사양
- 각 테스트케이스에 고유 ID가 있고 대상 요구사항/설계 요소로 추적된다 (GP2.2.1/GP2.2.3)
- 테스트 환경, 사전조건, 절차, 기대 결과가 명확히 기술되어 있다 (GP2.2.1)
- 요구사항 커버리지 근거(커버리지 매트릭스 등)가 존재한다 (GP2.2.3)
- 리뷰 및 승인 기록이 있다 (GP2.2.4)
- 베이스라인/버전 관리가 되어 있다 (GP2.2.2/GP2.2.3)

### 테스트 보고서/결과
- 실행 일자, 실행자, 대상 빌드/버전이 식별되어 있다 (GP2.2.3)
- 합격/불합격 결과가 결함(문제 보고서)과 연결되어 있다 (GP2.2.3)
- 커버리지 달성률과 미달 사유가 기록되어 있다 (GP2.1.2)
- 재테스트/회귀테스트 근거가 있다 (GP2.1.3)
- 검토·승인 기록이 있다 (GP2.2.4)

### 형상관리 계획서 + 베이스라인/변경이력
- 형상항목(CI) 식별 규칙이 정의되어 있다 (GP2.2.1/GP2.2.2)
- 베이스라인 생성 기준·시점이 정의되고 실제로 준수된다 (GP2.2.2/GP2.2.3)
- 버전관리 도구·저장소·브랜치 전략이 명시되어 있다 (GP2.2.2)
- 접근통제·백업 정책이 정의되어 있다 (GP2.2.2)
- 변경이력 로그(누가/언제/무엇을 변경)가 실제로 기록되어 있다 (GP2.2.3)
- 계획서상 형상관리 절차와 실제 수행 결과가 일치한다 (GP2.1.2/GP2.1.3)

### 리뷰 기록
- 리뷰 대상 산출물의 ID/버전이 식별되어 있다 (GP2.2.3)
- 참석자와 역할이 기록되어 있다 (GP2.1.6)
- 발견 사항과 심각도가 기록되어 있다 (GP2.2.4)
- 조치 완료 여부와 재확인(종결) 근거가 있다 (GP2.2.4)
- 리뷰 기준(체크리스트 등) 사용 여부가 확인된다 (GP2.2.1)

### 문제 보고서
- 고유 ID, 발견일, 발견자, 심각도/우선순위가 명시되어 있다 (GP2.2.1/GP2.2.3)
- 재현 절차와 영향 범위가 기록되어 있다 (GP2.2.1)
- 근본원인 분석 기록이 있다 (GP2.1.3)
- 조치 내역과 검증(재테스트) 결과가 연결되어 있다 (GP2.2.3)
- 상태 이력(미해결→분석→조치→검증→종결)과 종결 승인이 추적된다 (GP2.2.4)

### 변경요청
- 고유 ID, 요청자, 요청일, 사유가 명시되어 있다 (GP2.2.1/GP2.2.3)
- 영향분석(범위·일정·비용)이 기록되어 있다 (GP2.1.3)
- 승인/거부 결정과 승인자가 명시되어 있다 (GP2.2.4)
- 구현 완료 및 관련 산출물 갱신 여부가 추적된다(추적성) (GP2.2.3)
- 상태 이력(제출→검토→승인→구현→종결)이 남아있다 (GP2.2.3)

### 프로젝트 계획서 / 진척기록 (리스크 관리대장 포함)
- 목표, 일정, 마일스톤, 자원계획이 명시되어 있다 (GP2.1.1/GP2.1.2/GP2.1.5)
- 역할과 책임(R&R/RACI)이 정의되어 있다 (GP2.1.4)
- 리스크가 식별·평가되고 대응 계획이 있다 (GP2.1.3)
- 계획 대비 실적 모니터링 기록(진척보고, 이슈로그)이 있다 (GP2.1.2)
- 편차 발생 시 조정(재계획, 시정조치) 근거가 있다 (GP2.1.3)
- 계획 변경 이력이 관리된다 (GP2.2.3)

### 추적성 매트릭스 (교차 점검용)
- 요구사항-설계-구현-테스트 간 양방향 추적 링크가 존재한다 (GP2.2.3)
- 추적이 끊긴 항목(연결되지 않은 요구사항·설계·테스트)이 없다 (GP2.2.4)
- 최신 버전 기준으로 추적성이 갱신되어 있다(오래된 링크가 방치되지 않음) (GP2.1.3)

## 출력 형식

```markdown
## A-SPICE 4.1 CL2 심사 결과 — <프로세스 ID: 이름>

| PA | GP | 평정 | 근거 | 갭 | 권고사항 |
|----|----|------|------|----|---------|
| PA2.1 | GP2.1.1 | L | ... | ... | ... |
| ... | ... | ... | ... | ... | ... |

**종합 판정**: PA2.1 = <N/P/L/F>, PA2.2 = <N/P/L/F> → CL2 <달성/미달>

**주요 갭 및 권고**
- ...
```

여러 프로세스를 함께 점검할 경우 프로세스별로 위 블록을 반복하고, 마지막에 전체 요약 표(프로세스 × CL2 달성 여부)를 추가한다.

## 유의사항

- 이 스킬은 감사 결과를 **판정하고 근거를 제시하는 데** 집중한다. 산출물 파일 자체를 수정하지 않는다.
- 확인할 수 없는 항목(파일 접근 불가, 근거 부재)은 추측하지 말고 "확인 불가"로 명시한다.
- 공식 PAM 문서와 체크리스트 항목이 다르면 공식 문서가 우선한다.
